# Decisions

One row per binding decision. Newest last.

| Date | Decision | Why |
|---|---|---|
| 2026-10-11 | Patch set over pinned slot releases, not a fork and not a shim core | slot's owner declined more systems (slot#30). A shim would squeeze NES/SNES into the 240x160 GBA frame and the GBA shelf |
| 2026-10-11 | Cores: fceumm (NES default), nestopia (alt), snes9x (SNES default), snes9x2005_plus (alt) | Defaults on muOS, Knulli, ROCKNIX and NextUI for H700-class devices |
| 2026-10-11 | Reference device: Anbernic RG35XXSP (superseded 2026-10-12, see below) | The maintainer of this repo owns one |
| 2026-10-11 | Video: fixed per-platform 2x canvas (360x240 logical) | Smallest patch, GBA untouched. SNES hi-res blended 2:1 |
| 2026-10-11 | NES and SNES keep the GBA SP bezel on the RG35XXSP (640x427 window) | Same nostalgia look as GBA |
| 2026-10-11 | Real NES, Famicom, SNES and Super Famicom cart art with variants in v1 | Same depth slot gives GB, GBC and GBA carts |
| 2026-10-11 | SNES picture mode toggles with SELECT+X | L and R belong to the game on SNES; X is free in SELECT chords |
| 2026-10-11 | No new quick menu rows; NES/SNES shaders via SELECT+B/A | Keeps every upstream quick menu test unmodified (superseded 2026-10-13) |
| 2026-10-11 | Host struct field list untouched; new state in a side struct | Upstream in-source test `host_with()` lists every Host field |
| 2026-10-11 | macOS is the primary test job; Linux arm builds device artefacts | slot's host core tasks and headless render tests are macOS-only |
| 2026-10-12 | Two upstream test files get one token each (`| Platform::Nes` in chrome.rs, `| CartPlatform::Nes` in render_shelves.rs; Snes later) | Their helper matches over Platform are exhaustive, so a new variant cannot compile otherwise; check-upstream-tests.sh allows exactly these tokens |
| 2026-10-12 | `durability.rs` example value `cart_platform=nes` becomes `cart_platform=pce` | Upstream used `nes` as an unknown platform; NES is now real and must resume from `cart_platform=nes`; check-upstream-tests.sh allows only that value |
| 2026-10-12 | Upstream test edits happen only at five named sites, each checked exactly by `check-upstream-tests.sh`: `libretro.rs` one `#[cfg(test)] mod env_tests;`; `chrome.rs` `label_band` and `render_shelves.rs` `label_top` (`\| Platform::Nes` then optional `\| Platform::Snes` on the Game Boy arm, same with `CartPlatform`); `durability.rs` the one value `cart_platform=nes` to `cart_platform=pce`; `gpsp.rs` colour-correction match (`\| Core::Fceumm`, then optional `\| Core::Nestopia`, `\| Core::Snes9x`, `\| Core::Snes9x2005Plus` on the `Core::Mgba` arm). A future site may be added without asking only if it appends a variant token to an existing arm of an existing exhaustive match and is named in the guard; any other upstream test change stops and asks | Adding `Core::Fceumm` makes `gpsp.rs`'s match over `Core` non-exhaustive, so it cannot compile unchanged |
| 2026-10-12 | Carts show the real cartridge label art, never a screenshot; NES and SNES get a Cart Studio equivalent | Nostalgia: the shelf mirrors the physical carts. Asked the owner on slot #64 whether this lands as a PR to slot-cart-studio or a credited fork; a user-side fetch script (issue 41) is the fallback, and no Nintendo art is ever committed |
| 2026-10-12 | `HostExtra` holds only `canvas` in patch 0004; issue 14 adds `av_change` and `av_enable` to it (docs/PLAN.md and issue 14 Scope say so) | Nothing in 0004 reads the other two, and an unread field is dead code. The struct is append-only and `Host` is still untouched |
| 2026-10-12 | `Compositor::set_game_canvas` is called every frame from `Frontend::compose` and `GamePass::set_canvas` returns at once when the size is unchanged, not "on every core open" | One call site covers every way a core appears (open, eject then insert, core picker, resume). Unchanged frames cost one tuple compare. H3 (NES, eject, GBA equals H1) proves no stale texture |
| 2026-10-12 | `thumb::png_sized` lives in new file `thumb_sized.rs`; `thumb.rs` gets one `pub use` line so the path `thumb::png_sized` still holds | New code goes in new files (CONTRIBUTING section 3); `png` is unchanged |
| 2026-10-12 | `video_mode::source_rect` takes the canvas as a second parameter: `source_rect(platform, canvas, mode)`. `Core::canvas_f32` (new, in `core_policy.rs`) keeps the `app.rs` `picture_rect` hunk to one line | The old body derived the centring offsets from the fixed `SRC_W`/`SRC_H`. Its only caller is `App::source_rect`. No upstream test calls it |
| 2026-10-12 | Named `unsafe` exception: the GL texture re-allocation in `slot-gfx` `GamePass::set_canvas` (`DeleteTextures`, `UseProgram`, `Uniform2f`), next to `slot-retro`'s FFI | `GamePass` owns the texture and uniform locations and its other GL calls are already unsafe blocks in the same file. A safe wrapper would add a new GL helper to an upstream file |
| 2026-10-12 | `unsafe` is also allowed in our own new test files that must read GL output or a core symbol slot does not expose (`nes_window.rs`, `nes_fceumm.rs`) | Proving the NES window size and that fceumm consumed the overscan options needs the window pixels and `retro_get_system_av_info`, which slot has no safe API for; tests never ship to the device |
| 2026-10-12 | Reference and test device is the Anbernic RG34XXSP (720x480, 3:2), not the RG35XXSP | The maintainer's device is an RG34XXSP. Same H700 and stock OS, so the same zip. Its 720x480 panel is an exact 3x of GBA, so there is no bezel: GBA fills the screen and NES/SNES show at an integer 2x (512x480, 512x448), centred. The RG35XXSP bezel decision (640x427 window) still holds for 4:3 devices and stays covered by harness leg B1 and `nes_window.rs` |
| 2026-10-12 | NES and SNES default to the Stretch picture mode; GBA, GB, GBC keep upstream's Actual | Maintainer's device test: on the RG34XXSP's 720x480 panel the 2x NES/SNES picture left black bars. Stretch fills the screen (about 40% wider than 8:7); the per-game toggle switches back and is saved |
| 2026-10-13 | The quick menu Screen page lists a NES shader row on the NES shelf and an SNES shader row on the SNES shelf (Off, Grid, Dot, stored in `shader_nes` and `shader_snes`), in the place GBA and GB show their shader row. Reverses the 2026-10-11 decision "No new quick menu rows" for shaders. `QuickRow::SCREEN` stays 4 rows | Maintainer: users look for settings in the same place on every system. SELECT+A/B in game still works. Picture mode stays per cart and in game; upstream has no picture-mode row. The new variants are appended and the Screen row opens a page per shelf, so every upstream quick menu test is unmodified |
| 2026-10-13 | No fixed line limit on `app.rs` (the 25-line target is dropped); instead every upstream touch point is listed in `docs/UPSTREAM-TOUCHPOINTS.md` with a reason, `task check` fails on a stale or incomplete map, and each rebase reviews every row | Maintainer: what matters is knowing every point of contact with upstream so an update can be checked point by point, not a number |
| 2026-10-13 | slot remembers the last shelf and the selected cart of every shelf (by stem) across restarts, in `Config/shelf.state` (`shelf=<platform>`, `shelf_<platform>=<stem>`), not in slot.state. Saved through the state writer thread once the cursor is at rest; restored at boot unless a seated cart resumes | Users switch between five shelves and slot has no favorites or recents. A `SlotState` field would break the exhaustive `SlotState` literal in upstream `durability.rs`, which is outside the named test exceptions, so the memory gets its own file and slot.state stays byte-identical |
